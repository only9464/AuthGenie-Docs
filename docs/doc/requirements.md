## 二、软件系统描述

### 2.1 软件介绍

#### 软件名称
AuthGenie 许可证管理系统

#### 实现目标
1. 提供一个完整的软件许可证管理解决方案
2. 支持六大操作系统平台的许可证校验
3. 实现三级权限管理体系
4. 提供低延迟、高可用的服务
5. 控制成本，适合中小型软件企业使用

#### 开发背景
传统许可证管理方案存在以下问题：
- 部署复杂，需要自建服务器和数据库
- 成本高，服务器、CDN、运维费用昂贵
- 跨地域访问延迟高，用户体验差
- 扩展困难，需要手动增加服务器
- 多平台支持不足，各平台实现不一致

AuthGenie 采用 Cloudflare Workers 边缘计算架构，解决上述问题。

#### 适用领域
- 中小型软件企业的许可证管理
- 跨平台桌面应用的授权验证
- 移动应用的付费功能解锁
- SaaS 服务的订阅管理
- 软件毕业设计的参考实现

#### 不适用领域
- 超大规模企业级应用（日活 > 100 万）
- 需要完全离线校验的场景
- 对数据主权有严格要求的场景（数据必须存储在特定国家/地区）
- 需要深度定制数据库的场景

#### 应当包含的内容
- 用户注册与登录
- 团队管理
- 项目管理
- 许可证生成与管理
- 许可证校验 API
- 三级权限管理
- 审计日志
- Web 管理后台（用户端、管理员端、超级管理员端）
- 客户端 SDK（六大平台）

#### 不包含的内容
- 支付系统集成（许可证销售）
- 邮件通知系统
- 短信验证
- 第三方登录（微信、GitHub 等）
- 移动端 App（仅提供 SDK）

### 3.1 功能性需求 1 - 用户认证

#### 3.1.1 用户注册 (F-USER-001)

| 项目 | 内容 |
|-----|------|
| **名称、标识符** | 用户注册，F-USER-001 |
| **功能描述** | 允许新用户创建账号，填写用户名和密码 |
| **优先级** | 高 |
| **输入** | username（字符串，2-20 字符）, password（字符串，6-32 字符） |
| **操作序列** | 1. 用户访问注册页面<br>2. 输入用户名和密码<br>3. 点击注册按钮<br>4. 系统验证输入<br>5. 检查用户名是否已存在<br>6. 创建用户记录<br>7. 返回注册成功 |
| **输出** | { success: true, userId: number, message: string } |
| **补充说明** | 用户名必须唯一，密码明文存储（后续版本改进为哈希） |

#### 3.1.2 用户登录 (F-USER-002)

| 项目 | 内容 |
|-----|------|
| **名称、标识符** | 用户登录，F-USER-002 |
| **功能描述** | 验证用户身份，返回 JWT Token |
| **优先级** | 高 |
| **输入** | username（字符串）, password（字符串） |
| **操作序列** | 1. 用户访问登录页面<br>2. 输入用户名和密码<br>3. 点击登录按钮<br>4. 系统验证凭据<br>5. 生成 JWT Token<br>6. 存储会话到 KV<br>7. 返回 Token 和用户信息 |
| **输出** | { success: true, token: string, user: { id, username } } |
| **补充说明** | Token 有效期 24 小时，支持刷新 |

#### 3.1.3 用户登出 (F-USER-003)

| 项目 | 内容 |
|-----|------|
| **名称、标识符** | 用户登出，F-USER-003 |
| **功能描述** | 用户退出登录，使 Token 失效 |
| **优先级** | 中 |
| **输入** | JWT Token（从请求头获取） |
| **操作序列** | 1. 用户点击登出按钮<br>2. 系统接收请求<br>3. 从 KV 删除会话<br>4. 返回登出成功 |
| **输出** | { success: true } |
| **补充说明** | 客户端需自行清除本地存储的 Token |
